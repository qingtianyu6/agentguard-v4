# Audit and trace evidence scope

New `v2:` audit rows hash the preceding digest, trace ID, event type and canonical payload together. The verifier still checks earlier V3 payload-only rows without upgrading or rewriting them. Audit appends now use a database head-version compare-and-swap; concurrent thread and process tests on SQLite confirm a single chain. This does not make the business action and audit append one transaction, and it does not stop a database administrator from rewriting all rows. A separately retained signed export can reveal later changes to that exported snapshot.

`GET /api/v1/audit/traces/{trace_id}/evidence-bundle` returns a trace snapshot, a canonical SHA-256 digest, and explicit limitations. If `AGENTGUARD_EVIDENCE_SIGNING_KEY_FILE` points to an Ed25519 PEM private key and the audit chain verifies, the complete bundle is signed. An incorrectly configured key or broken audit chain prevents a signed export. Without a key, the response remains explicitly unsigned.

Generate a key pair outside the repository with `python scripts/evidence_keys.py keygen --private <private.pem> --public <public.pem>`. Keep the private key at the configured server path and distribute the public key through a trusted channel. Verify an exported API response offline with `python scripts/evidence_keys.py verify <bundle.json> <trusted-public.pem>`; the CLI accepts either the complete API response or its `data` object. Verification requires the caller's pinned public key and checks the content digest, audit-chain status, signer key ID, and signature over the full bundle.

New decisions store the normalized action, completed history, policy/contract values, and tool trust snapshot used at decision time. Older decisions may lack these snapshots; additional policy rows in an export reflect export-time state. A signature authenticates an export made with the configured key, but does not protect an untrusted signer, guarantee transactional audit writes, or prove that every external tool side effect was captured. Independent key custody, database append guarantees, and replay remain necessary for the final design-book evidence chain.
