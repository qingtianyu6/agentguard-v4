# Strict profile boundaries

Set `AGENTGUARD_SECURITY_PROFILE=strict` with distinct `AGENTGUARD_GATEWAY_TOKEN` and `AGENTGUARD_APPROVER_TOKEN`. Gateway action and session routes require the gateway credential. Management and read APIs under `/api/v1/` require the approver credential; health and version are public. The signed ToolHive webhook is separately authenticated by its HMAC secret. Live WebSocket subscriptions require the approver credential in the handshake header. Demo login, refresh, profile and demo API keys are disabled in strict mode. Sandbox profile remains for local demos.

The frontend does not yet implement a real human identity provider or credential mediation, so this service-token profile is for an isolated service deployment, not a publicly exposed user portal. Keep both tokens out of agents and browsers, use TLS and an upstream identity-aware admin proxy, and limit network reachability. Tokens must differ. Existing SQLite tables are created on startup; production deployments require explicit migrations and independent secret rotation. ToolHive webhook UID replay records must be pruned after their timestamp expiry by operational maintenance; no automatic retention task is configured.
